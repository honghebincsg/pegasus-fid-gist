# ANC 航班信息与 ATIS 看板 · 交接说明

版本：1.0.2　更新日期：2026-11-20　适用对象：接手开发/维护人员

## 1. 项目概述

这是一个 Windows 桌面程序 + GitHub 云端抓取的组合方案：

- **桌面程序**：MYGO（Go）+ Vue 3（本地打包），左侧菜单切换「航班看板」和「ATIS 查询」
- **航班看板（FID）**：显示 CSN 在 ANC（安克雷奇）的航班与停机位，每 60 秒刷新
- **ATIS 查询**：输入 4 位 ICAO 机场代码，查询 Arrival / Departure ATIS
- **云端**：GitHub Actions 抓取数据，GitHub Gist 存储最新 JSON；cron-job.org 每 5 分钟触发 FID 抓取

## 3. 环境要求

本地开发：

- Windows 10 及以上，安装 **WebView2 Runtime**（Windows 11 自带）
- **Go 1.27.3+**；首次构建建议设置 `GOPROXY=https://goproxy.cn,direct` 和 `GOTOOLCHAIN=auto`
- **go-winres**：`go install github.com/tc-hib/go-winres@latest`
- Python 3.10+ 仅云端脚本需要；本机调试不依赖

网络可达性：

- 桌面程序需要访问 `api.github.com`、`gist.githubusercontent.com`、`atis.info`、`atis.guru`
- `github.com` 在国内时通时断，部署/修改仓库建议走 `api.github.com`

## 4. 本地运行与调试

直接运行：

```bat
双击 desktop\anc-fid.exe
```

源码构建：

```bat
cd desktop
go-winres make
go build -ldflags="-H windowsgui" -o anc-fid.exe .
```

说明：

- `-H windowsgui` 保证双击运行不弹出控制台
- `//go:embed all:frontend` 会把 `frontend/`（含 `vendor/`）嵌入 exe，分发时无需额外静态文件
- 修改前端后重新 `go build` 即可，不需要额外打包步骤

应用内 ATIS 接口（MYGO 自定义协议，**不监听本地端口**）：

```text
GET http://ancapi.localhost/atis?code=EHAM
```

也可以用 URL 参数直接打开查询页：

```text
/?page=atis&code=EHAM&auto=1
```

### 开发热更新

```bat
cd desktop
dev.bat
```

- 前端（`desktop/frontend/`）保存后，窗口约 1 秒自动刷新
- Go 文件（`main.go`、`atis.go`、`token_*.go`、`go.mod`）保存后，脚本自动 `go build` 并重启窗口
- 开发窗口加载 `http://127.0.0.1:5173`（仅 `dev.bat` 启动的开发服务器；生产程序不监听任何本地端口）
- 开发构建产物在 `desktop/.dev/`，不纳入仓库

### Token 读取顺序

1. 环境变量 `GH_DISPATCH_TOKEN`
2. 本地文件 `%LOCALAPPDATA%\anc-fid\dispatch_token.txt`
3. 程序内置常量（`desktop/token_local.go`）

> 内置 token 的值不在本文档中记录；`token_local.go` 已加入 `.gitignore`，不要把包含该文件的源码上传到公开仓库。

## 6. 数据流与关键逻辑

### 航班看板（FID）

1. cron-job.org 每 5 分钟触发 GitHub Actions
2. Actions 抓取 Pegasus FID 接口 `POST /F/C/ajaxgetflights.php`（`fid=CSN&cust=CSN`）
3. 结果覆盖写入 Gist 的 `fid_latest.json` / `fid_flights.csv` / `fid_status.json`
4. 桌面程序每 60 秒读取 Gist 并渲染

### ATIS 查询

1. 先尝试本机直连 **atis.info**（美国机场，约 1–4 秒）
2. 失败或非美国机场 → 本机直连 **atis.guru**（约 1–3 秒）
3. 两者都失败 → 触发 GitHub Actions 重新抓取并等待结果；**不会再直接读取 Gist 旧数据**
4. 本机抓取成功时，后台异步触发 Actions，把同一份结果同步到 Gist（不阻塞界面）
5. Gist 文件按机场命名：`KLAX.json`、`PANC.json`、`EHAM.json` 等，每个机场一个 JSON
6. 机场无 ATIS 时，JSON 写入 `"ok": false` 与错误说明，界面直接提示
7. 界面底部标注**获取方式**：
   - `本机直连源网站`：直接访问 atis.info / atis.guru
   - `GitHub Actions 抓取后从 Gist 读取`：本机抓取失败，经 Actions 重新抓取后读取 Gist

## 7. 已知限制

- 内置 token 会随 exe 分发；不要转发给无关人员。建议换成只授权 `pegasus-fid-gist`、仅 Actions 读写的 fine-grained token，替换 `token_local.go` 后重新编译
- GitHub Actions 冷启动约 10 秒；本机直连 atis.info / atis.guru 通常 1–4 秒
- Gist raw 有约 5 分钟 CDN 缓存；程序读取时带 `?t=` 时间戳绕过
- atis.info 只覆盖美国机场（其他机场返回 404，自动回退 atis.guru）
- 目标站偶发网络抖动/Cloudflare 拦截；程序有重试与回退逻辑
- cron-job.org 免费账户最多 50 个任务、2 个通知渠道
- 开发热更新使用本地 5173 端口（仅 `dev.bat`）；生产程序不监听任何本地端口

## 8. 故障排查

| 现象 | 处理 |
| --- | --- |
| 提示“未配置 GitHub token” | 检查 `GH_DISPATCH_TOKEN`、本地 token 文件、`token_local.go` |
| ATIS 显示旧数据 | 已修复：本机失败会让 Actions 重新抓取；若仍出现，检查 Actions 运行是否失败 |
| Actions 403 | fine-grained token 缺 Actions 写权限 |
| Actions 422 | Gist 删除不存在的文件；脚本已修复（只删除已存在文件） |
| Gist 文件 404 | 文件名应为 `<机场码>.json`（大写），确认脚本版本 |
| Actions 不触发 | 检查 cron-job.org 任务 HISTORY，或手动 workflow_dispatch |
| 页面空白/样式丢失 | 确认 `frontend/vendor/vue.global.prod.js` 存在并已重新构建 |
| 启动即退出 | 用 `go build`（不带 `-H windowsgui`）运行查看日志；确认 WebView2 已安装 |
| 中文乱码 | 编码探测顺序 UTF-8 → GB18030 |
